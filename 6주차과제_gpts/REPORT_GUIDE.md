# 과제 제출 구상: Data Chef AI 한 개의 프로젝트로 4·5번 수행

## 보고서 4번: GPTs 이해 및 맞춤형 AI 설계

1. 사용자 문제: 냉장고 속 재료로 적합한 요리를 고르기 어려움, 라벨 해석이 어려움
2. Data Chef AI의 역할과 사용자: 식재료/수량/제약 조건을 받는 레시피 코치 + 성분표 도우미
3. 개발 방식: 맞춤 GPT 생성 UI와 **GPT API 앱은 별개**. 본 프로젝트는 GPT-6 Luna API를 사용한 Streamlit 웹앱임을 명시하고, 교수자가 GPT 생성 UI를 반드시 요구하는지 확인
4. Instructions: `ai_service.py`의 레시피 생성·라벨 분석·냉장고 사진 인식 지시문
5. Knowledge: `data/recipes.json` (기본 레시피), `data/demo_nutrition.csv` (100g 근사값), `data/compatibility.csv` (조리 조합 점수)
6. 구체적 구현: 모델 구조화 응답 → 파이썬 검증 → 점수 산출 → 결과 표현
7. 동일 사용자 재료로 API 모드와 기본 모드의 결과 비교

## 보고서 5번: 응용 예제 만들기 / 평가

- 시나리오 A: 계란·두부·시금치 조합으로 20분 저녁 추천
- 시나리오 B: 동일 조건에서 알레르기 '난류'를 제외했을 때 추천 목록 변화
- 시나리오 C: `재료 활용` 가중치를 올렸을 때 점수와 순위 비교
- 시나리오 D: 냉장고 사진 판독 후 수량을 수정하여 입력으로 사용
- 시나리오 E: 포장식품 성분표에서 100g/1회 제공량 차이를 제대로 읽는지 확인
- 시나리오 F: 재고에 없는 재료가 필요한 레시피에서 부족량을 제대로 표시하는지 확인
- 시나리오 G: 자료에 없는 재료 질문, 흐린 성분표 사진에 대해 불확실성을 표시하는지 확인

### 실험 기록 양식

| 테스트 | 입력 | API 사용 | 기대 결과 | 실제 관찰 | 수정 사항 |
|---|---|---|---|---|---|
| A | 계란 2개, 두부 150g 등 | 사용 | 레시피 3개 및 점수 | 실행 후 기입 | 관찰 후 기입 |
| B | A와 같음 + 난류 회피 | 사용 | 계란 포함 후보 제외 | 실행 후 기입 | 관찰 후 기입 |
| E | 시판 제품 성분표 | 사용 | 보이는 수치·기준량 식별 | 실행 후 기입 | 관찰 후 기입 |

**미실행 항목을 성공했다고 쓰지 마세요.** API 실사용은 실제 계정 키로 테스트한 뒤 캡처를 제출합니다.

### 핵심 알고리즘

`Score = 30*IngredientCoverage + 30*NutritionSuitability + 20*ExpiryPriority + 10*TimeFit + 10*PairCompatibility`

모든 요소는 0~1 범위로 정규화해 사용합니다. 기본 배점은 사용자가 변경할 수 있고 내부에서 총점 100으로 다시 환산합니다. 위 숫자는 연구로 검증된 최적값이 아니라 학습용 임의 가중치입니다.

### 강점과 한계

강점: 생성형 AI가 제안한 요리를 그대로 신뢰하지 않고 제한조건/영양 데이터/점수를 재검증합니다. 잘못된 재료·알레르기 조건을 가진 후보를 자동 제외합니다.

한계: 기본 영양 데이터는 근사치, 등록 재료 범위 제한, 알레르기 매핑 불완전, AI 이미지 판독 오류, 실제 섭취 목표는 개인 차이가 큼. 따라서 건강/안전 관련 결정에는 사용하지 않습니다.

### 부록에 넣으면 좋은 내용

- Streamlit 완성 화면 스크린샷
- API 모델명이 `gpt-6-luna`인 설정 코드
- 추천 결과 JSON
- 성분표 판독 결과 JSON
- 테스트 기록표 및 실패 사례
- GitHub 저장소 URL과 Streamlit 배포 URL(실제 생성한 주소만 기재)
